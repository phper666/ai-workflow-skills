# 契约生成规则

## 事实优先级

1. 当前共识文档和已生效决策记录。
2. 已冻结 OpenAPI 或对外接口契约。
3. 当前代码、Flyway migration 和真实测试。
4. Jira Story、评论和附件。
5. 原始需求、旧文档和历史聊天。

发现上层事实冲突时停止固化相关字段，登记开放问题。

## Schema

- API DTO 与 Entity、数据库记录、第三方 SDK 对象分离。
- 每个字段明确类型、必填、可空、长度/格式、枚举、默认值和敏感性。
- 不用 `Map<String,Object>` 代替稳定 Schema。
- Secret、Token、密码只写不读；响应只返回掩码或已配置状态。
- 时间使用仓库约定；无约定时使用 UTC ISO 8601，并说明展示层时区转换。
- ID 示例使用真实格式，禁止 `1`、`0`、`string`、`test` 等占位值。

## HTTP 与错误

- HTTP 状态表达协议语义，业务错误码表达具体原因。
- 参数错误、未认证、无权限、不存在、状态冲突、业务校验、限流、依赖失败和超时分别定义。
- 未知异常不得暴露堆栈、SQL、内部地址或第三方原始响应。
- 每条业务规则至少对应一个成功或失败场景。
- 在三个或以上接口重复且语义、响应要求、客户端处理和重试性完全一致的异常，应抽取为具名公共异常集。
- 每个接口必须明确列出适用的公共异常集，并用独立矩阵列出本接口特有异常；没有特有异常时明确写“无特有异常”。
- 公共异常集和特有异常矩阵合并后，必须覆盖 HTTP、语义错误码、精确触发条件、响应字段要求、客户端处理和可重试性。
- 相同 HTTP 但触发字段、权限对象、客户端处理或重试性不同的异常不得强行合并。
- 错误码段尚未冻结时，仍定义稳定、可读的语义错误码名称，并标明其编号或外层结构受哪个开放问题约束；不得只写“错误码 TBD”。

## 逐接口字段展开

- 每个接口独立列出 Header、路径、查询参数和请求体字段；没有某类输入时明确写“无”。
- 每个成功响应独立列出字段路径、类型、必有性、可空性、来源/约束和说明。
- 共享 Schema 用于消除定义漂移，但不能代替接口视角的字段展开；接口表至少展开前端和测试直接读取的所有字段路径。
- 只把真正受待确认项影响的字段标记为 `TBD(Q-xxx)`，其余已知字段继续明确类型和约束。
- 对同一个接口给出不含敏感信息的请求/响应示例；认证字段未冻结时，可只展示非敏感字段并说明被省略的 Schema 与问题编号。

## 分页、排序和筛选

- 明确页码起点、默认值、最大页大小和稳定排序。
- 排序字段使用白名单，不承诺任意字段排序。
- 空列表返回空集合，不返回 `null`。

## 幂等、状态与异步

- 创建、执行、重试和导出必须明确重复请求行为。
- 每个状态转换定义触发者、前置条件、目标状态和非法转换结果。
- 异步操作定义任务状态、查询方式、过期、失败和重试规则。
- 未关闭的状态机或幂等开放问题不得通过“常见做法”补齐。

## 外部系统

- 定义认证方式、连接/读取/总超时、重试条件和退避上限。
- 非幂等操作默认不自动重试。
- 请求超时但结果未知时，必须先定义结果确认方式。
- 可配置地址考虑 SSRF、协议、端口、域名和网段限制。

## 数据库

- 以 Flyway 为数据库结构主源。
- 对 PostgreSQL 行为使用 PostgreSQL 语法与约束，不生成 MySQL DDL。
- 说明主键、唯一约束、外键、检查约束、索引和时间字段。
- 已发布 migration 不修改；新增变更使用新 migration。
- spec 只描述终态和 migration 文件，不累积多个版本 ALTER 全文。

## 示例值

优先级：原型或测试夹具真实值 > 代码真实枚举 > 业务合理构造。邮箱使用 `example.com`，Secret 使用明确掩码，不使用真实个人或生产数据。

## 当前态文档

- 主体只描述当前应实现的契约。
- 已关闭问题从 pending 删除，结论合入对应字段或规则。
- 不保留删除线、历次审查编号、废弃方案和立场演变。
- 变更记录单条不超过 200 字。
- 同一 Story 始终更新同一路径；禁止生成版本副本规避增量合并。
- 每次执行重新扫描当前来源。已有文档只是待更新基线，不是事实优先级更高的输入。
- 已关闭问题必须有决策、共识或代码与上层事实一致的证据；合入结论后删除对应 `TBD` 和开放问题行。
- 未关闭问题即使已有临时代码也不能自动关闭，必须记录实现与共识的差异。
- 来源无变化时重复执行应产生零语义 diff；格式化或重排不能成为无业务变化的输出噪声。
