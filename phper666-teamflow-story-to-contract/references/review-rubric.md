# Jira 接口契约审查规约

## Blocker

### TRACE-01 追踪断裂

接口、Schema 或状态规则无法追溯到 Story、共识规则、决策或验收编号。

### OPEN-01 擅自关闭开放问题

把 `TBD`、开放问题或建议基线写成确定契约，且没有生效决策记录。

### API-01 接口详情缺失

接口缺用途、鉴权、逐字段请求表、逐字段成功响应表、失败响应声明、幂等/冲突或测试要点中的必要部分；失败响应未明确列出公共异常集和特有异常，或只写“见公共异常”，视为缺失。

### API-02 Schema 或示例不可执行

字段类型、必填性、枚举或格式不明确；示例含 `string`、`test`、无语义的 `0/1`；请求与响应不符合 Schema。

### API-03 规则没有失败契约

合并接口声明的公共异常集与特有异常后，必填校验、状态约束、权限、唯一性、幂等或依赖失败仍没有对应 HTTP、语义错误码、精确触发条件、响应要求、客户端行为和可重试性。

### API-04 字段没有在接口中展开

请求或成功响应只引用共享 Schema，没有在接口详情中展开调用方实际发送或读取的字段路径、类型、必填/必有、可空和约束。

### SEC-01 敏感信息泄露

响应、示例、日志或审计差异包含完整 Secret、Token、密码、Authorization、Cookie 或不必要的 PII。

### AUTH-01 鉴权或租户隔离不明确

受保护接口没有服务端权限要求，或资源未说明如何绑定当前租户/组织。

### CONS-01 契约内部冲突

接口清单、Schema、接口详情、测试场景或 OpenAPI 对同一字段/状态给出不同定义。

### DATA-01 实现证据冲突

文档声称字段入库、唯一或可重试，但当前代码、migration 或外部契约提供相反证据。

### REPEAT-01 重复执行不收敛

同一 Story 重复执行时创建第二份契约、保留已关闭问题或对应 `TBD`、未重新扫描当前代码/Flyway/OpenAPI/相关契约，或者在来源无变化时产生无意义语义 diff。

### TASK-01 子任务提示门禁错误

自动流程中存在未关闭 P0 或未标优先级的待确认项，却主动提示创建后端 Jira 子任务；或者把 P1/P2、Blocker/Major/Minor 错误地作为绝对禁止创建的条件。用户明确要求创建时不适用该自动提示门禁。

### TASK-02 未确认即写入 Jira

没有先展示完整后端子任务预览并获得用户明确 `y`，就创建 Jira 子任务或修改父 Story 状态；没有把经办人设置为当前已认证 Jira 用户；存在 P0 时没有说明任务受阻和不得实现未决部分；或者替前端、测试等其他角色创建子任务。

### TASK-03 重复创建后端子任务

父 Story 已存在同模块 `BE` 子任务，却没有先报告并获得更新现有任务的独立确认，就创建第二个重复后端子任务。

## Warning

### COMPAT-01 兼容影响未说明

删除字段、改变类型/枚举/必填性、修改路径或状态语义，但没有兼容策略。

### TEST-01 测试覆盖不足

缺少参数、权限、冲突、外部依赖失败、敏感信息或数据结果验证。

### DOC-01 文档膨胀

包含已闭环过程、废弃方案、重复审查日志、多份自检或超过 1200 行且没有合理拆分。

### EVIDENCE-01 复用结论证据不足

使用“沿用、参照、复用”但没有 `文件:行号`；涉及数据或权限时没有第二层证据。

### DOC-02 公共异常重复

同一异常在三个或以上接口中以完全相同语义重复定义，没有抽取为具名公共异常集；或公共异常集过度抽象，导致接口实际触发条件不清楚。

## 验证步骤

1. 对照 Story、共识、开放问题和验收标准检查追踪矩阵。
2. 逐接口检查请求字段表、成功响应字段表、公共异常集引用、特有异常矩阵、状态、幂等和测试；失败响应必须能由公共集与特有项完整合并。
3. 对照 OpenAPI 检查路径、字段、枚举和状态码。
4. 对照代码和 migration 检查已有行为与数据库结论。
5. 搜索敏感字段、占位值、`TBD` 和历史痕迹。
6. 已有契约时检查已关闭问题是否合入正文、开放项是否保持、实现差异是否处理，以及无来源变化时是否保持零语义 diff。
7. 检查后端子任务创建门禁：自动提示时未关闭 P0 为 0；明确创建时允许存在 P0 但必须标记受阻；P1/P2 不阻止提示；预览完整、写入需独立确认、经办人为当前 Jira 用户，且未替其他角色或重复创建任务。
8. 检查 Markdown 链接并执行 `git diff --check`。

最多执行两轮。第二轮仍有 Blocker 时停止并交由用户或业务负责人裁决，不继续自动重写。
