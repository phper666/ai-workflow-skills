# 多版本策略

共识文档/契约文档在多版本迭代下的演进规则。核心原则：**文档是"演进式单一文档"，不是"每版本一份"**——正常迭代一份文档到底，归档是文档瘦身手术（非日常操作）。

## 版本语义

| 版本 | 含义 | 分支 | 归档 |
|:-----|:-----|:-----|:-----|
| **vX.Y 次版本**（v1.1/v1.2...） | 向后兼容的功能迭代 | 同分支（dev） | ❌ 不触发 |
| **vX.0 主版本**（v2.0/v3.0...） | 可能破坏兼容/架构级/重构 | 新分支演进 | ⚠️ 改动大才触发 |

版本号是**绑定锚点**（契约绑定共识版本、待确认项绑定版本+规则编号、变更传播沿版本差异），不是文档副本编号。

## 演进原则（正常迭代）

```
v1.0 → v1.1 → v1.2 → ...：同一份共识文档持续演进
- 规则表加行（新规则 CON-R 新编号，状态=新增）
- 结论更新（规则表"当前结论"列改值，状态=变更中）
- 版本号升 + 变更摘要（≤200 字）
- 下游绑定更新：契约/待确认项绑定新版本号
- 变更传播：改了的规则沿编号传播，没改的不动
```

**不归档、不复制、无 -v2 文档副本**（文档防膨胀的核心机制）。

## 归档触发条件（精确）

```
触发 = 主版本变更（v1→v2）且 旧内容被替换/下线超过 ~50%
不触发 = 追加式（v2 只是加模块但旧内容全保留）/ 正常迭代（v1.1 加功能）
```

归档是"手术"——只在正文要换血时做。

## 归档操作

1. 新建归档文档：`{模块名}-共识文档-v1归档.md`
2. v1 下线/被替换内容移入归档（带"下线原因 + 下线版本"标注）
3. 正文只留当前生效内容（当前态原则）
4. 规则索引更新：下线规则状态=已下线（指向归档文档）
5. 变更记录追加一条归档说明（≤200 字）

## 分支约定（多版本并行时）

```
dev 分支：        持续迭代（v1.0 → v1.1 → v1.2 → v2.0 演进）
release/vX 分支： 线上稳定线（vX 发布时冻结 + git tag）
hotfix：          release/vX 分支修复 → 发布 → cherry-pick 到 dev
v2.0 启动：       dev 演进 v2 共识（release/v1 冻结，只修 bug）
```

与 my-opencode-stack 的 `docs/trail/VERSIONING.md` 分支策略对齐（dev/main/release 分支 + cherry-pick）。

## 场景操作速查

| 场景 | 操作 |
|:-----|:-----|
| v1 上线后加功能 | 同分支：共识升 v1.1 → 新规则/新契约 → 传播检查 → 交付 |
| v1 线上 hotfix | release/v1 分支：共识 v1.x 补丁 → 传播 → 契约更新 → cherry-pick 到 dev |
| v2 大功能（追加式） | dev 演进 v2.0 → 新模块章节追加 → 不归档（旧内容保留） |
| v2 大重构（替换式） | dev 演进 v2.0 → 旧内容 >50% 下线 → 归档 → 正文换血 |
| v2 发布 | release/v2 冻结 + tag → v1 分支只修 bug |

## 纪律

- 版本号必须升（防下游绑定错乱），但文档不复制
- 归档只在"替换式大变更"时做，追加式永不归档
- 变更摘要每条 ≤200 字，不累积旧过程
