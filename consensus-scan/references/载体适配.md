# Q-items 载体适配

待确认项（Q-items）载体由 `docs/spec/团队配置.md` 指定。skill 主体只写抽象字段，平台差异在本文件描述。两平台均支持，选择后尽量不变；更换只需迁移 Q-items 数据，流程逻辑不变。

## 通用字段（两平台一致）

| 字段 | 说明 |
|:-----|:-----|
| 编号 | Q-001 起，全局唯一，去重依据 |
| 问题 | 单条问题描述（含触发场景） |
| 优先级 | P0（阻断）/ P1 / P2 |
| 契约影响 | BLOCKER / MAJOR / MINOR |
| 待确认角色 | PM / BE / FE / QA |
| 创建人 | 发起视角或人名 |
| 共识版本 | 绑定基线版本 |
| 章节/规则编号 | 定位锚点（变更传播依赖） |
| 状态 | open / answered / closed |
| 回答 | 单义结论 + 适用范围 + 生效时间 |
| 回写位置 | 强制：共识文档章节/规则号 |
| 复核人 | 发起人 |

## 飞书多维表格

- 用 `lark-base` 系列工具操作（建表、写记录、更新记录）
- 负责人字段填人名（来自团队配置角色映射）
- 表名：待确认项；视图按状态/待确认角色分
- 操作：`manage_bitable_record` action=search/create/update，filter 按编号/状态

## Jira

- 载体：q-item 子任务类型（挂在父需求下）
- 字段映射到 Jira 自定义字段或描述结构（编号/优先级/共识版本/规则编号等，按团队约定）
- 经办人 = 待确认角色对应的账号（团队配置映射）
- 操作：按 `story-to-contract` 适配器接口的 createItem/addComment/listItems 语义执行
- 状态：open=To Do / answered=In Review（等待复核）/ closed=Done

## 双向语义

- 三角色 → PM：扫描发现的问题，待确认角色=PM
- PM → 三角色：PM 建问题给 BE/FE/QA 确认（拆解、评审、写共识时的疑问），待确认角色=对应角色
- 谁回答问题谁填"回答"字段；**回写位置由创建人复核时校验**
