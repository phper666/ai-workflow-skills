# Q-items 载体适配

待确认项（Q-items）载体由 `docs/spec/团队配置.md` 指定。**原则：载体 = 团队现有 PM 平台（5 选 1），同平台管理工作项与待确认项，推广阻力最小；飞书多维表格是"无 PM 平台团队"的默认。**

skill 主体只写抽象字段，平台差异在本文件描述。五平台均支持；选择后尽量不变，更换只需迁移 Q-items 数据，流程逻辑不变。

## 通用字段（五平台一致）

| 字段 | 说明 |
|:-----|:-----|
| 编号 | Q-001 起，全局唯一，去重依据 |
| 问题 | 单条问题描述（含触发场景） |
| 优先级 | P0（阻断）/ P1 / P2 |
| 契约影响 | BLOCKER / MAJOR / MINOR |
| 待确认角色 | PM / BE / FE / QA |
| 创建人 | 发起视角或人名 |
| 共识版本 | 绑定基线版本 |
| 章节/规则编号 | 定位锚点（变更传播依赖） |
| 状态 | open / answered / closed |
| 回答 | 单义结论 + 适用范围 + 生效时间 |
| 回写位置 | 强制：共识文档章节/规则号 |
| 复核人 | 发起人 |

## 飞书多维表格

- 接口选择（按执行环境，**先检测再用**）：
  - **环境有飞书 MCP 工具**（`feishu_manage_bitable_record` 等）→ 用 MCP：`feishu_manage_bitable_record` action=search/create/update，filter 按编号/状态
  - **环境只有 lark-cli** → 加载 `lark-base` skill，用 `lark-cli base` 等价命令操作（建表/写记录/更新/查询）
  - 两套接口语义等价：表名"待确认项"，字段见"通用字段"，视图按状态/待确认角色分
- ⚠️ **批量创建已知问题**：`batchCreateRecords` 在部分身份（UAT）下报 `WrongRequestBody`（实测 2026-08）；批量写失败时**降级为单条循环创建**（create 一次一条），不影响语义
- 负责人字段填人名（来自团队配置角色映射）

## Jira

- 载体：q-item 子任务类型（挂在父需求下）
- 字段映射到 Jira 自定义字段或描述结构（编号/优先级/共识版本/规则编号等，按团队约定）
- 经办人 = 待确认角色对应的账号（团队配置映射）
- 操作：按 `story-to-contract` 适配器接口的 createItem/addComment/listItems 语义执行
- 状态：open=To Do / answered=In Review（等待复核）/ closed=Done

## TAPD

- 载体：缺陷或需求类型（约定类型名如"待确认项"，建议用缺陷——轻量、不污染需求树）
- 字段：TAPD 自定义字段承载（编号/优先级/待确认角色/共识版本/规则编号/回写位置）；回答放描述/评论
- 状态：open=新建 / answered=处理中（等待复核）/ closed=已关闭
- 操作：按 `story-to-contract` 适配器（adapters/tapd.md）语义执行

## Linear

- 载体：Issue + label `q-item`（编号/角色用 label 或自定义字段）
- 字段：自定义字段（优先级 P0/P1/P2、待确认角色、共识版本、规则编号、回写位置）；回答放 description 或评论
- 状态：open=Backlog/Todo / answered=In Review / closed=Done
- 操作：按 `story-to-contract` 适配器（adapters/linear.md）语义执行；Linear 的 label+状态+优先级结构天然贴合 Q-items 模型

## GitHub

- 载体：Issue + labels（`q-item`、`q-p0`/`q-p1`/`q-p2`、`q-be`/`q-fe`/`q-qa`/`q-pm`）
- 字段：Projects v2 自定义字段承载结构化信息（共识版本/规则编号/回写位置）；回答写 Issue body 或评论
- 状态：open=Open / answered=标签 `q-answered` / closed=Closed
- 操作：按 `story-to-contract` 适配器（adapters/github.md）语义执行；assignee=待确认角色

## OpenProject

- 载体：自定义工作项类型"待确认项"（UI：管理 → 工作包类型 → 新建，类型名为 Q-item 或待确认项）
- 字段：description 结构化承载（编号/共识版本/规则编号/回写位置/回答），优先级用优先级字段（建议 UI 改 P0/P1/P2）
- 状态：open=New / answered=In progress 或自定义"待复核"状态 / closed=Closed
- 操作：按 `story-to-contract` 适配器（adapters/openproject.md，REST API v3）语义执行
- 认证：`OPENPROJECT_URL` + `OPENPROJECT_API_KEY`（API key 唯一可靠，2FA 用户密码认证禁用）

## 双向语义

- 三角色 → PM：扫描发现的问题，待确认角色=PM
- PM → 三角色：PM 建问题给 BE/FE/QA 确认（拆解、评审、写共识时的疑问），待确认角色=对应角色
- 谁回答问题谁填"回答"字段；**回写位置由创建人复核时校验**
