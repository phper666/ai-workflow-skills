# 扫描规则库

扫描规则 = 把"曾经踩过的坑"变成"每次扫描自动检查"。规则库两级结构：

## 项目规则

- 位置：项目内 `docs/spec/扫描规则.md`
- 内容：本项目反复出现的问题升级而来
- 生效范围：仅本项目扫描

## 共享规则

- 位置：**skill 分发仓库**（`consensus-scan/references/扫描规则库.md` 的共享区，随 skill 分发/更新同步到全团队）
- 内容：跨项目验证有效的经验升级而来
- 生效范围：所有接入本工作流的项目扫描自动加载
- 升级条件：同一坑在 ≥2 个项目/模块验证过，或团队复盘确认可复用

## 规则格式

每条规则一条：

```markdown
- [RULES-xxx] {检查点}：{扫描时如何检查}。来源：{项目/日期/编号}，验证：{已解决 N 例}
```

示例：

```markdown
- [RULES-001] 分页接口：共识文档未定义分页/排序/筛选语义时标 Q-item，不默认"前端分页"。
- [RULES-002] 幂等：涉及资金/库存/写入的接口，共识未定义幂等策略时标 BLOCKER。
- [RULES-003] 跨端：交互规则只写了 Web 未写移动端时标 Q-item，不默认两端一致。
```

## 升级流程

1. 踩坑记录（`docs/lessons/`，被动）
2. 同一坑第二次出现 → 复盘确认可复用
3. 项目规则：写入项目 `docs/spec/扫描规则.md`
4. 跨项目有效 → 提交到 skill 分发仓库共享区 → 全团队生效

## 验证机制

- 规则升级后若产生假阳性（误报）→ 团队发现后撤下或改写
- 假阳性是自纠信号：说明规则描述太宽或前提不清，收敛触发条件后重新上线
