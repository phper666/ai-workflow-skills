# 共识扫描与待确认闭环

执行工作流步骤 3-4：**三角色扫描 → 去重聚类 → 待确认项创建/闭环 → 复盘升级**。原则：角色是视角不是人头——一个人可以带不同帽子分批扫描，但**视角必须全覆盖**。

## 模式

- **默认（单人三角色）**：agent 自动分批切换 BE → FE → QA 三视角，分别扫描后合并。用户零参数。
- **`--role=BE|FE|QA`**：只跑指定视角（分工明确或只关心单视角时）。多视角跑完需执行 Phase 3 merge 收口。
- PM 不参与扫描（PM 是回答闭环的人，不是挑问题的人）。

## Phase 1：扫描

输入：共识文档（当前版本）。

按视角扫描（维度与 `story-to-contract` Phase 4 一致，直接复用其问题分类语义）：

| 视角 | 检查重点 |
|:-----|:---------|
| BE | 状态转换合法性/触发条件/冲突行为；数据唯一性/删除/版本/事务/隔离；鉴权/租户隔离；第三方认证/超时/重试/限流/部分失败；一致性 |
| FE | 页面/字段/交互/空态/跨端差异；字段类型/必填/枚举/来源/默认值 |
| QA | 验收口径可观察性（成功/失败/安全/兼容场景）；边界/异常路径；可测试性 |

问题格式（统一）：

```
[BLOCKER][Q-007][后端] 订单取消并发下库存回补可能重复扣减，幂等未定义。
```

- 前缀：契约影响（`BLOCKER`=改变字段/状态机/鉴权/幂等/事务/隔离；`MAJOR`=可搭框架不可宣告验收；`MINOR`=按既有约定即可）+ 编号 + 视角/角色
- 编号连续：`Q-001` 起，查 Q-items 载体现有编号避免冲突
- 自动关闭已有答案的问题：共识、决策记录或代码已明确回答的 → 记录来源，不重复提交

## Phase 2：去重聚类

- 按编号去重（不同载体中的同一问题不重复计数）
- 绑定：共识版本 + 章节 + 规则编号
- 分级：业务优先级 P0（阻断）/ P1 / P2（未标按 P0 处理，直到补齐优先级）

## Phase 3：merge 收口（分角色跑后）

合并各视角报告：交叉引用相同问题、合并为合并问题集、输出"视角覆盖确认"（哪几个视角已跑，哪些缺）。

## Phase 4：待确认项创建/更新（Q-items）

按 `docs/spec/团队配置.md` 的载体配置写入（适配细节见 `references/载体适配.md`）：

- **创建**：新问题写入载体，字段：编号/问题/优先级/待确认角色/创建人/共识版本/章节/规则编号/状态
- **双向**：谁有问题谁建——PM 也可建问题给 BE/FE/QA 确认（字段"待确认角色"指定），不限于三角色→PM 方向
- **自动挂载**：`团队配置.md` 有角色账号映射 → 自动 assignee=对应账号（Jira 经办人 / 飞书负责人字段）；无账号 → 指定人名；映射缺失 → 提示登记
- **不重复创建**：载体中已有同一编号问题 → 更新而非新建

## Phase 4.5：状态流转前置检查

闭环流转（open→answered→closed）前必检：

1. 读 `docs/spec/团队配置.md` 的 `status_map`（抽象状态 → 载体实际状态名/guid）
2. 缺失或未配置 → **先跑 workflow-setup Phase 4.5（状态就绪检查）**，不静默失败
3. 状态映射存在 → 按映射流转：answered=移动到"已回答"列（或对应状态）、closed=完成/关闭
4. 飞书任务场景：answered=移动 section、closed=完成任务（completed_at）或移动到"已关闭"列

## Phase 5：闭环校验（回答 → 回写 → 复核）

PM（或待确认角色）回答后：

1. 回答必须单义：结论 + 适用范围 + 生效时间
2. **回写校验（强制）**：回答必须写入共识文档（结论进正文、未决项行关闭、回写位置字段填章节/规则号）——回答本身不是闭环，**回写才是**
3. 复核：发起人确认回答真正消除歧义（单人全干时退化为自查，回写强制保留）
4. 三连全过 → 状态 closed；缺任一 → 打回

## Phase 6：复盘升级（步骤 12 侧）

触发：同一个坑第二次出现，或用户说"复盘扫描规则"。

- 验证该问题是否可复用（不是一次性特例）
- 升级为扫描规则：**项目规则**（写本项目扫描规则文件）或**共享规则**（提交到 skill 分发仓库的共享规则库，全团队所有项目生效）
- 规则库两级结构见 `references/扫描规则库.md`

## 产出确认

扫描完成后汇报：各视角问题数、P0/P1/P2 分布、已自动关闭的、新增 Q-items 编号列表、待回答角色、视角覆盖情况。
