# 项目概览扫描

<role>
新人/AI 进项目时，用「先概览后详情」的方式了解项目现状（有哪些模块/做到哪/最近改了什么），不一次全量扫所有文档，避免上下文爆炸。
</role>

## 触发门槛

用户说以下任一 → 进概览扫描：
- "分析项目 / 项目概览 / 了解项目 / 扫描项目"
- "看到哪里了 / 项目做到哪 / 最近改了什么 / 项目进度"
- 新会话开始，需要快速定位项目状态

## 流程（先概览后详情）

### P1 读概览/索引类文档（小文件，先读）

用 glob/固定路径找「概览/索引/摘要/配置」类文档（都是小文件），不读详情文档：

1. **项目导航/入口**：仓库根 `AGENTS.md`（或 README）——项目入口、文档地图、红线
2. **配置类**：团队配置/项目配置（含载体、角色、模式等）
3. **索引/摘要类**：用 glob 找 `*索引*`、`*摘要*`、`*变更*`、`*状态*` 类文件——这些是「项目全貌」的小型索引。**摘要/变更类文件也可能很长**（如模块级变更摘要上百条），先读头部/最近 N 条，或用 grep 按关键词定位最近条目，不全量加载长摘要
4. **版本/进度**：找版本记录、进度记录类（各模块的当前版本/完成度）。版本/进度常编码在文件名前缀（期/批次标识，如 S1/B1/T1）里，无独立版本文件时从文件名/索引推断；如需确认具体版本，看对应模块文档的版本记录章节

读完这些 → 得出「项目有哪些模块 / 做到哪个版本 / 最近改了什么 / 有哪些在途事项」。

### P2 按需读详情（做需求时才读）

- 要做具体需求 → 按「需求标识」glob 定位该需求相关文档（如 `ls docs/api/*<需求标识>*`），只读命中文件；同时读该需求的共识文档当前态（`docs/spec/共识-<模块>-<需求标识>.md`，只读最新版本，历史演进看变更摘要）
- 需要某模块细节 → 读该模块对应文档，不读全部

> P1 输出概览后停下，等用户指示/确认；用户要求做具体需求时才进 P2 读详情。

### P3 禁止

- **禁止全量扫**：`ls docs/` 全列 + 读所有文档（每份文档都读一遍）
- 禁止把「概览」当成「读全部详情」——概览阶段只读索引/摘要/配置类小文件

## 关键命令/模式

- 找索引：glob `**/*索引*`、`**/*摘要*`、`**/*变更*`
- 找入口：读仓库根 `AGENTS.md` / `README.md`
- 找配置：读团队配置/项目配置（AGENTS 导航段指的位置）
- 定位需求：glob `docs/api/*<需求标识>*`、`docs/design/*<需求标识>*` 等

## 注意事项（红线）

- 概览 = 读「小文件索引」，不是「读所有文档」
- 详情按需（做需求/需要细节时），不预先全读
- 项目大不是问题——索引/摘要永远是小文件，先读它们定位，再按需详情
