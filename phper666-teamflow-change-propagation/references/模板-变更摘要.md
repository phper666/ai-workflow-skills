# 变更摘要模板

共识文档业务规则变更时生成。**三层结构（方案 B″）**：

- **L1 全局索引** `docs/spec/变更摘要.md`：每版本一行（日期|模块|规则#|一句话|指向模块文件），永小
- **L2 模块详情** `docs/spec/变更摘要-<模块>.md`：每条 ≤200 字（模块 = 按项目实际划分，如 桌面壳/看板/订单…）
- **L3 归档** `docs/spec/变更摘要-<模块>-<年份>.md`：L2 模块文件 >100 条 或 跨年 → git mv 轮转，指针永远指向当前文件

L2 模块文件同时承担**版本记录**职能：版本行（`## 日期 v版本`）即共识文档的版本索引，共识文档附录版本记录只留指针，不复制详情。

范式参考：datahub 项目 `业务规范-CHANGELOG.md`（日期+版本分组、规则编号驱动、取代链、反哺 Q-items）。

### L3 归档（docs/spec/变更摘要-<模块>-<年份>.md）

L2 模块文件 >100 条 或 跨年 → `git mv docs/spec/变更摘要-<模块>.md docs/spec/变更摘要-<模块>-<年份>.md`，新建当前文件，指针永远指向当前文件。

## 单条条目规范

- **delta-only**：只记规则/契约/流程变化，不记过程叙述、评审流水账
- **编号驱动**：每条以规则编号开头（新增 / 修订 / 下线 / 取代）
- **取代链**：新规则取代旧规则时，旧条目与新增条目互相可追溯——新条目写"取代 D-0xx"，旧条目可留一行"已由 <日期> v<版本> / <新编号> 取代"（不改写历史，只加标注）
- **反哺 Q-items**：规则变化源于待确认项结论时写来源编号（"Q-003 结论"）
- **单条 ≤200 字**；描述旧→新语义变化，不写过程叙述

## 不追加变更摘要的场景

- **契约评审修订**：评审流水账归 `docs/records/` 或 `docs/design/`，不追加变更摘要
- 变更摘要只记规则/契约/流程变化——纯文档措辞、实现细节、评审过程不进

## 变更类型参考

- 语义跟随：描述/取值变化，无兼容影响
- 破坏兼容：字段删除、接口路径/类型变化、行为反转
- 敏感类：涉及权限、数据、资金、状态机、事务、隔离
- 新增：新增规则（非变更，若影响下游同样传播）
- 下线：规则删除（记录原因与取代物）

## 版本记录约定

- 版本行 = 版本记录：`## <日期> v<版本号>`，一句话列出本版本规则变化摘要
- 共识文档"附录与版本记录"表：`版本 | 日期 | 变更摘要条目引用`——一行指针，详情在 `变更摘要-<模块>.md`
- 版本号与共识文档升版本同步（phper666-teamflow-consensus-doc Phase 2），禁歧义命名
